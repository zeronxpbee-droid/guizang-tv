# MiTV-MFTP0 待机唤醒自动进入

## 授权与目标

用户明确要求遥控器开机或待机唤醒后进入归藏，同时保留可回退方案。该需求不授权替换默认 Home、停用或清除小米组件、Root、无障碍服务、悬浮窗、删除应用数据、发布 Release 或合并 PR。

## 改动前证据

- 设备为 `MiTV-MFTP0` / Android 9 / `23.2.10.6129`，当前 `boot_count=72`。
- `boot_auto_play=0`；可见 `start_3rd_app` 已被固件消耗为空字符串，原始回退基线也是空字符串。
- 应用旧偏好为 `enabled=true`、`attempted=72`，状态是“已在本次开机后进入桌面”。
- 系统事件日志显示，后续待机唤醒时小米 `BootActivity` 再次启动归藏 `BootGateActivity`；旧代码按同次完整启动重复调用退出。

## 实现边界

- 设置拆分为“关闭”“仅完整重启”“完整重启＋待机唤醒”；旧 `enabled=true` 自动迁移为“仅完整重启”。
- 待机模式只允许 `MiTV-MFTP0`，不把 MTSU0 或未知机型的完整启动记录外推为待机兼容。
- 同一 `boot_count` 的入口调用只在用户选择待机模式后放行，30 秒内的重复调用拒绝。
- 继续使用小米已经调用的轻量 `CATEGORY_INFO` Activity；不新增权限、Receiver、Service、无障碍或悬浮窗。
- Home 键、小米原桌面和完整启动模式继续保留。关闭应用内模式后，即使小米缓存继续调用入口也会立即退出。
- 该功能只能在系统允许第三方 Activity 显示后进入归藏，不能声称移除或跳过系统启动阶段广告。

## 回退

1. 在“设置 → 电视与启动 → 开机与唤醒”选择“仅完整重启”或“关闭”。
2. 需要完全恢复时，再把 `start_3rd_app` 恢复为改动前的空字符串；不要清除小米桌面数据。
3. 同签名覆盖升级保留现有壁纸、首页、Codex 配对及其他偏好；禁止通过卸载解决问题。
